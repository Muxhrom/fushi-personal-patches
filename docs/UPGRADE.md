# 迁移到官方新版

## 目标与输入

目标：跟随官方稳定版，同时保留 Windows 的自动复制开关及原版在线服务功能。输入包括本仓库、目标版本的官方源码和官方安装包，以及用户本机已有的安装与配置。优先处理稳定发布，不必逐次追随日常开发提交。

## 操作流程

1. **确认是否仍需补丁。** 阅读新版设置和文本采集实现；若已存在等效开关，验证其行为后优先使用官方实现。
2. **确定精确基线。** 对照官方包版本、对应源码提交、Flutter 引擎及原生组件。不要用最新开发分支代替某个已安装稳定版的源码。
3. **建立独立工作副本。** 遵循新版本自己的 `AGENTS.md` / 构建说明，保护现有未提交改动。上游 remote 的 push URL 保持禁用，所有发布仅限用户授权的私有仓库。
4. **检查补丁适用性。** 先执行 `git apply --check`。如果失败，检查重命名、文件移动、设置架构、偏好仓储、文本会话和剪贴板接口的变化。需要三方合并时，确认 Git 已拥有清单中原基线的对象，再使用 `git apply --3way --index` 并逐处处理冲突；不要删除冲突标记后直接宣称完成。
5. **按新版契约适配。** 首选新版已有的文本发布和剪贴板接口。保留下面的功能约定，避免把旧版实现整块覆盖到新架构。
6. **测试与构建。** 使用对应版本的 SDK、锁定依赖和上游补丁流程，执行功能测试与相关守卫；再验证实际 Windows 剪贴板。按 `BUILD_AND_SERVICES.md` 保留在线服务。
7. **验证后安装。** 先在隔离环境中运行；确认已有恢复副本、原程序已退出，才替换安装文件。用户个人资料与账号数据不得混入测试环境。
8. **更新维护资料。** 重生成针对新基线的完整补丁，收齐 untracked 的新增文件；更新 `manifest.json`、文件校验值与本次验证结果，扫描敏感信息后推送到这个私有仓库。

## 必须保留的行为

- Windows 设置开关，默认关闭，启停即时生效，重启后保留选择。
- 仅复制正式发布的选定文本流；使用新版已有的线程选择、会话和时间过滤规则。
- 开启时不复制历史，不因线程切换或音频/收藏等通知重放旧台词。
- 相同行 ID 的正文补全能更新剪贴板；不同新行即使正文相同也按新行处理。
- 异步写入有序，旧写入不会覆盖已完成的新写入。
- 禁用、关闭和新会话取消待执行写入；单次错误不阻断下一句。
- 实现属于应用级生命周期，不依赖设置页或捕获工作台是否打开。

## 维护补丁和清单

导出时使用明确的文件白名单，并包含新增文件。直接执行 `git diff` 会漏掉尚未纳入 Git 的新控制器和测试；可以在独立工作副本中仅暂存功能文件，再导出 `git diff --cached --binary --full-index <base-sha>`。

不要把在线服务配置文件、工作区协调规范、机器路径或缓存夹带进补丁。清单必须同时记录基线 SHA、补丁 SHA-256、受影响文件、原/新 Git blob 和修改后内容 SHA-256。对精确基线执行 `git apply --check`、实际应用并逐文件校验；这样未来能确认保存的补丁完整对应已验证的功能。
